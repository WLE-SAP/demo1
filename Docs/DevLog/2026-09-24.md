## 10:15 ~ 10:40 · 图片资源改成「一物一图」，开始界面背景与按钮也支持图片（无图片时程序绘制）

**目标**：用户要求「修改提供图片资源的方式，减少复用，采取一物一图的方式，同时主界面的背景和按钮也需要兼容图片（无图片时使用程序绘制）」。
旧方案是**按原素材名**匹配：一张 `rect.png` 同时决定房屋屋顶/墙体/门窗 + 木箱 + 村民身子 + 农田垄 + 围栏，
一张 `disc.png` 同时决定树冠 + 村民头 + 羊 + 水井 + 花 + 路灯 + 地洞 + 各种高亮底衬 ——
美术想单独换其中任何一个都做不到；而且开始界面完全不受这套系统影响。

**做了什么**

  一个 key 放多张图会**只用先载入的**并在 Console 点名；名字没对上 key 的图片列进 `UnmatchedFiles`。
  **旧的按素材名匹配（`rect` / `disc` / `roundrect` / `marker` / `grass`）已删除**。

  只有颜色本身承载信息的 key 保留染色（村民身/头 = 职业色与肤色、窗/路灯/炉火 = 昼夜变色、
  高亮底衬、花与篷布的随机配色、界面面板与按钮）。规则写在 `Slot.tint` 里，逐 key 可查。
- **`VillageGenerator` 每个物件挂自己的 key**：`AddRect` / `AddDisc` / `AddSlice` 末尾新增 `key` 参数，

## 10:55 ~ 11:20 · HUD 改版：面板不遮挡、体力条移到底部居中、等级越高条越长

**目标**：用户要求「修改游戏内 hud，不要遮挡，血条移到屏幕正下方，等级越高血条越长」。

**做了什么**
- **体力条挪到屏幕正下方居中**：`SimpleHUD.LayoutPanels` 里把它的锚点设成
  `anchorMin = anchorMax = (0.5, 0)`、`pivot = (0.5, 0)`、`anchoredPosition = (0, staminaBottomMargin)`，
  不再跟在左上角两块面板下面（原来它在「说明 → 状态」之后，是三块里最下面那块）。
  Fill 在底衬里是左对齐的（`pivot.x = 0`），所以条变长时从中间往两边长、消耗时仍然从右往左退。
- **等级越高血条越长**：条长 = `staminaBarWidth`（初始 460）+ `level × staminaWidthPerLevel`（默认 110），
  即 0/1/2/3 级 → 460 / 570 / 680 / 790（画布单位）；长大 = 体力上限更高，条也跟着变长才看得出来。
  等级没变就不改 RectTransform（`lastBarLevel` 缓存），避免每帧触发重排。
  Fill 的宽度 = (条长 − 内缩×2) × 体力比例，内缩与高度在 `Awake` 里从场景读出来，不用手填。
- **面板不再遮挡**：`LayoutPanels` 现在先按**文字的实际高度**收面板（`FitPanel`：`TMP.preferredHeight + 边距`，
  说明边距 28 / 状态边距 20），再按实际高度从上往下排；状态行文字换行 / 变长时（`Update` 里比较
  `preferredHeight`）重新排一次，所以面板永远包得住文字、也不会压住下一块。
  实测原来「操作说明」面板高 262 而文字实际要 311 —— **文字是溢出的**，现在面板 339 = 311 + 28，刚好包住。
- 顺带修掉一个会让上面整套逻辑失效的崩溃：`SimpleHUD.Awake` 里取初值时会读
  `BugController.NearbyBurrow`，而它在 `BugController.Awake` 里用 `rb.position`；HUD 比小虫先跑时
  `rb` 还是 null → `NullReferenceException`，整个 `Awake` 从中断处往下都不执行（版式全没生效）。
  已改为 `rb != null ? rb.position : (Vector2)transform.position`（写进 Spec 红线 16）。
