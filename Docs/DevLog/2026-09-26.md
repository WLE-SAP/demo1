# 2026-09-26 · 开发日志

## 09:45 ~ 10:10 · 建筑碰撞体缩成「脚印」+ 房屋集群/独户分布 + 人口按房屋密度（只在玩家看不见的地方刷新）

**目标**：用户一条需求里给了三件事 ——
①「修改代码，去除建筑物周边的透明碰撞箱」；
②「房子要按照概率生成：大部分房子呈现集群的方式聚集，在路边和水井边更容易出现；也有小部分的房屋会单独出现，
此时他们的周围一般有大片农田等生产设施，而一般没有道路经过」；
③「npc 的刷新也会根据房屋的密集程度而调整，去除我之前讲过的屏幕内一定要有四个 npc 的限制，
所有 npc 的刷新必须是在玩家视线被遮挡的地方」。

开工时先按 §8.1 读了 `Spec.md` 与记忆；两处歧义问过用户（AskUserQuestion）：
①碰撞箱怎么处理 → 用户答「**把碰撞箱的体积缩小成长为建筑图案的宽，高为长的三分之二**
（即小虫可以躲在房子的后面，从主视角看来被遮挡）」；
②「视线被遮挡」按哪个标准 → 用户答「**屏幕外 或 被挡住**」。

**做了什么**

1. **建筑碰撞体 = 脚印**（`VillageGenerator.AddBuildingFootprint`）：宽 = 建筑图案的宽、
   高 = `min(图案的高, 宽的 2/3)`、**底边压在建筑底边上**。`AddWholeBuilding` 新增
   `out Rect drawn` 重载，把「图实际画到哪儿」（物体本地坐标）交出来；分件房子用整块占地当图案。
   落到六种房型的 `CreateHouse`、`BuildExtraHouse`、`BuildCastle`、`BuildWindmill`、
   `BuildPowerPlant`、`BuildBellTower`。副作用正是用户要的：房子上半截能走进去，站在那儿的小虫
   Y 更大 → `YSort` 序号更小 → 画在房子底下 = 「躲在房子后面」。
2. **房屋分布重做**（`BuildHouses` → `BuildHouseClusters` + `BuildIsolatedHouse`）：
   - 集群：先抽 1~4 个**集群中心**（`PickClusterCenters`：按 `roadClusterShare` 决定落在**路边**
     （`TryPickRoadSidePoint`）还是**水井 / 喷泉边**（`TryPickWellSidePoint`，用新加的 `PickOwnVillageAnchor`
     从锚点表里筛出**本区块**那口井、并用区块自己的 `rng` 抽 —— 用 `VillageMap.PickNear` 会走
     `UnityEngine.Random`，区块内容就不再是「坐标 + 种子」的纯函数了，红线 29），两个中心至少隔一个 `clusterRadius`），
     房子围着中心长；
   - 独户：离最近的路（**含隔壁区块伸过来的那段路**，新 `RoadDistance` + `SegmentDistance`）≥ `isolatedRoadClearance`、
     与别的建筑留 `isolatedSpacing`、**大多数要求边上放得下那片大农田**（`CanHostSteading`），
     在合格落点里**挑离别的建筑最远**的一个（`NearestBuildingDistance`）；
     落下去后铺田（`BuildSteading`）并把「房子 + 田」外扩 `loneYard` 登记进 `occupied`，后面的集群不能贴上来；
   - `BuildFarm` / `BuildPen` / `BuildGarden` 拆成「抽位置」+「按给定地块画」（`CreateFarm` / `CreatePen` / `CreateGarden`）；
   - 参数按聚落进 `WorldBiome.ApplySettlement`：独户比例 农村 0.22 / 城市 0.12 / 荒野 1，
     集群个数 2~3 / 3~4 / 1，`steadingChance` 0.85 / 0.5 / 0.5。
3. **人口按房屋密度**：`BuildVillagers` 改成 `round(本区块房子数 × WorldBiome.VillagersPerHouse(聚落) × 随机 0.75~1.25)`
   再夹在 `villagerMin/Max`（农村 1~8 / 城市 2~10 / 荒野 0~1）；入住率 农村 0.45 / 城市 0.6 / 荒野 0.5。
   生成结果记进 `VillageGenerator.LastVillagerTarget` → `VillageWorld.chunkPopulation`。
4. **补人只在玩家看不见的地方**：`VillageWorld.EnsureVillagersInView`（旧「屏幕里至少 N 个村民」）**删除**，
   换成 `MaintainPopulation()`：按 `chunkPopulation[当前区块]`（+ `extraPopulation`，混乱 4 级会加）比活人数，
   少了就补，落点必须过 `IsHiddenFromPlayer`（相机视野之外 **或** 从小虫望过去被静态碰撞体挡住，
   `IsLineOfSightBlocked` 只认「没有刚体」的碰撞体），还要 `Physics2D.OverlapCircle(0.55)` 为空；
   找不到就不补。删掉 `WorldBiome.MinVillagersInView` / `MaxExtraPerChunk` / `KeepVillagersInView`
   与 `VillageWorld.viewHalfSize` / `extraMinVillagers`（改名 `extraPopulation`）；`ChaosMeter` L4 跟着改。
   新增验证入口：`IsOnScreen` / `IsHiddenFromPlayer` / `PopulationTargetOf` / `LastRespawnPoints` /
   `VisibleRespawnViolations` / `RespawnedVillagers`（加进 `VillageWorld`，带注释说明是调试 / 验证用）。

## 10:30 ~ 10:50 · 修「虫子头部的显示优先级太高，场地挡不住」（排序偏移的语义）

**目标**：用户紧接着报：「虫子头部的显示优先级太高，场地挡不住」——
正好是上一轮把建筑碰撞体缩成「脚印」之后暴露出来的：能钻进屋顶下面了，但**头**还是画在屋顶外面。

**查到的三个真因（都是「`YSort` 的偏移语义」被用错）**

1. `YSort` 把每个子渲染器**初始的 `sortingOrder` 当成相对偏移**缓存，`scale` 是**每世界单位 10 档**，
   而 `Bug/Head` 写的是 **20**（`Bug/Body` 那根 LineRenderer 写 10）→ 头部等于「硬往前挤 2 米」，
   房子的排序按自己的中心 Y 算，于是头顶戳在屋顶外面（实测头部 order = `YOrder(小虫) + 20`）。
   改成 **尾巴 +1 / 头 +2** 就正常了。
2. `YSort.Cache()` 原来只收 `SpriteRenderer`，而**小虫的尾巴是 `LineRenderer`** → 它根本不在排序表里，
   永远停在写死的绝对序号（实测 `order = 10`，等于一直画在整个世界后面）。改成缓存 `Renderer`。
3. 顺带发现同类 bug：`ItemCatalog.Create` 给 Visual 写的是**绝对** `YOrder(点) + orderOffset`，
   然后又挂 `YSort` → **Y 被算两遍**（实测木桶 / 石头 / 水泵的 Visual 序号比应得的高 **1300+**，
   等于永远画在所有东西前面）。现在按模式给：挂了 YSort 只给相对偏移（`orderOffset` 默认 10 → 1），
   没挂 YSort 的（电线）才给绝对 `yOrder + 偏移`；`ContentPack` 的灯笼跟着从 14 改成 2。

- 修改：`Assets/Scripts/ItemCatalog.cs`（Visual 的排序按 `useYSort` 分两种语义；`orderOffset` 默认 1）
