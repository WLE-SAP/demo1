# 开发日志（DevLog）

## 1. 规则（每次开发都必须遵守）

1. **一次开发 = 一条记录**：按日期写在 `Docs/DevLog/YYYY-MM-DD.md` 里；
   当天已有文件就**追加**一节 `## HH:MM ~ HH:MM · 本次做了什么`，不要另建文件、不要覆盖旧内容。
2. **必须带时间**：用本机时间（Asia/Shanghai），格式 `YYYY-MM-DD HH:MM`；跨天的开发分别在两天各写一条。
3. **必须写「涉及文件」**：新增/修改的文件路径列出来（AI 靠这个快速定位改动面）。
4. **必须写「怎么验的」**：跑过什么命令 / 看过什么运行时数据 / 有没有实机验证过。
   **没验证就写「未验证」**，不要用「应该没问题」这种说法。
5. **必须写「遗留问题 / 下一步」**：没有就写「无」。
6. 规则变更、红线、格式要求这类**长期约定写进 [`Spec.md`](Spec.md)**，不要只写在日志里。
7. 资源格式（图片 / 音频）的规范在项目根目录 [`README.md`](../../README.md)；
   **新增或改名资源 key 时，要同步更新那份 README 和 `Spec.md` 的 key 表**。

> 补记过去的开发时，在标题后标注「（补记）」，时间按当时实际工作时间写；不确定的时间写实际记录时间并说明。

## 2. 模板

新建记录直接复制 [`TEMPLATE.md`](TEMPLATE.md)。
